## Explanation

## Valid Sequence — Greedy
Idea

We need the lexicographically smallest index sequence, so scan word1 from left to right and always take the earliest feasible index.

Maintain:

j → next character of word2 to match.
skip → whether the one allowed mismatch is already used.
last[j] → position where word2[j...] can be matched exactly.
Build last[]

Scan both strings from right to left:

if (word1[i] == word2[j]) {
    last[j] = i;
    j--;
}

This tells us whether the remaining suffix can fit after a candidate index.

Greedy

For each word1[i]:

word1[i] == word2[j]

→ exact match, take it.

Otherwise, we may use our one mismatch if:

skip == 0 && (j == m-1 || i < last[j+1])

The second condition means the remaining word2 can still be matched after i.

Take the first feasible index because that guarantees the lexicographically smallest index array.

## My Notes

## Mistakes
Sliding window is not applicable here: this is a subsequence problem.

Prefix array is unnecessary; j already tracks the matched prefix.

Not knowing how to calculate last[]: scan backwards and greedily match word2.
Using the mismatch without checking whether the suffix can still be matched.
Forgetting that lexicographic order applies to the indices, not the resulting string.
Complexity
Time:  O(n)
Space: O(m)

The key pattern is:

Greedy earliest choice + precomputed future feasibility.
