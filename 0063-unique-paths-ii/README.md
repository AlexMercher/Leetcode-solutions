# Unique Paths II — Explanation

`dp[i][j]` = number of ways to reach cell `(i,j)`.

For an obstacle:

```cpp
dp[i][j] = 0;

Otherwise, a cell can be reached only from:

above: (i-1, j)
left: (i, j-1)

So:

if(i > 0)
    dp[i][j] += dp[i-1][j];

if(j > 0)
    dp[i][j] += dp[i][j-1];

We start the loops from 0 because obstacles can occur in the first row/column, so they must be processed explicitly.

In Unique Paths I, we initialized the first row and column to 1, so we could start from 1.

Here, we cannot do that because an obstacle makes all cells after it in that direction unreachable.

The explicit i > 0 and j > 0 checks prevent accessing outside the grid.

Base case:

dp[0][0] = 1;

unless the starting cell itself is an obstacle, in which case the answer is 0.

Complexity

Time: O(m × n)

Space: O(m × n) for the 2D version.
