## Explanation

Why lower_bound?

Because the subsequence must be strictly increasing.

We want the first:

tails[pos] >= x

and replace it with x.

That maintains the smallest possible tail for that subsequence length.

For a non-decreasing subsequence problem, the search changes to:

upper_bound(...)

which is an important variation to remember.

How to recognize LIS

Whenever you see:

subsequence
+
preserve order
+
strictly increasing/decreasing
+
maximize length

immediately think:

LIS

Then decide:

Need simplest explanation?
    → O(n²) DP

Need optimal complexity?
    → tails + lower_bound
    → O(n log n)

The subtle but important fact is:

tails does not necessarily contain the actual longest increasing subsequence. Its length is the LIS length.

So this is a great example of a DP problem where a greedy invariant + binary search completely removes the quadratic transition.
