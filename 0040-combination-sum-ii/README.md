## Explanation

Algorithm — ≤150 words
Sort candidates so equal values are adjacent. Use backtracking to build each combination. At each recursion level, try candidates from index onward. After choosing candidates[i], recurse with i + 1 because each array element can be used only once. If sum == target, store the current combination. Since the array is sorted, stop the loop when sum + candidates[i] > target, because all later values will also be too large. To avoid generating duplicate combinations, skip a candidate when:
if(i > index && candidates[i] == candidates[i-1])
    continue;

This skips duplicate choices at the same recursion level, while still allowing duplicates at deeper levels, e.g. [1,1,2].

## My Notes

#Mistakes
Your first mistake was:
backtrack(candidates, index + 1, ...)

It must be:
backtrack(candidates, i + 1, ...)

because i is the element you actually chose; the next recursion must start after that element.
You also initially forgot to initialize:
n = candidates.size();

Then, when using a set<vector<int>>, you were still generating enormous numbers of duplicate combinations. The all-1s testcase exposed this: the set removes duplicates after generating them, so the recursion still explodes. Skipping duplicates at the same recursion level prevents that repeated work:
if(i > index && candidates[i] == candidates[i-1])
    continue;

Finally, sorting is necessary both for this duplicate-skipping technique and for safely using break when the current value makes the sum exceed the target.
