## Explanation

Example:

[0,1,2,4,5,6,7]

Rotated:

[4,5,6,7,0,1,2]

The minimum 0 is exactly where the array goes from:

7 → 0

So there is a pivot where the ordering breaks.

What does binary search need?

We need a way to decide:

Which half contains the minimum?

Take:

[4,5,6,7,0,1,2]

Set:

left = 0
right = 6
mid = 3

So:

nums[mid] = 7
nums[right] = 2

Now notice:

7 > 2

This tells us the rotation point/minimum must be to the right of mid.

Why?

Because if mid is larger than the rightmost element, we're sitting in the left sorted portion, and the smaller rotated portion must be after it.

So:

left = mid + 1;
Opposite situation

Suppose:

[6,7,0,1,2,4,5]

Again:

mid = 3
nums[mid] = 1
nums[right] = 5

Now: 1 < 5
This tells us the minimum is at mid or to the left of mid.

So:right = mid;
Notice not mid - 1, because mid itself could be the minimum.

“If middle is bigger than the right end, the minimum is to the right; otherwise the minimum is at or to the left of middle.”

---

## My Notes

int mid = right + (left - right) / 2;

Mathematically this looks like:

(left + right) / 2

but integer division in C++ truncates toward zero, so it does not always behave like the usual midpoint.

The case that breaks it

Suppose:

left = 0
right = 1

Your formula:

mid = 1 + (0 - 1) / 2
    = 1 + (-1)/2
    = 1 + 0
    = 1
