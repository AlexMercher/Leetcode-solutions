## Core Idea

Use DP to determine whether the **current player can win** with `i` stones.

```text
dp[i] = true  → current player can force a win
dp[i] = false → current player will lose
```

### Base Case

```cpp
dp[0] = false;
```

With no stones, the player cannot make a move and loses.

## Recurrence

From `i` stones, we can remove any square:

```text
1², 2², 3², ...
```

After removing `j²`, the opponent gets:

```text
i - j²
```

If that state is losing:

```cpp
if (!dp[i - j*j])
```

then the current player can make that move and win.

Therefore:

```cpp
dp[i] = true
```

if **any** legal square move reaches a losing state.

## Why Two Loops?

The outer loop processes every DP state:

```cpp
for (int i = 2; i <= n; i++)
```

The inner loop tries every possible square move:

```cpp
for (int j = 1; j*j <= i; j++)
```

Unlike problems such as Climbing Stairs, the transition is not fixed to a few states; the possible moves grow with `i`.

## Complexity

There are `n` states and up to `√n` square moves per state.

```text
Time:  O(n√n)
Space: O(n)
```
