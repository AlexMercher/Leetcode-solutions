Second pop

Top is c:

Stack is empty.

But we want:

"ca"

Why did we get "ac"?

Because a stack is LIFO:

Last In → First Out

We pushed:

c
a

so we pop:

a
c

Therefore you correctly do:

reverse(ans.begin(), ans.end());

which gives:

"ac"
 ↓
"ca"

Final answer:

"ca"
Whole dry run in one table
char    operation        stack

'a'     push             [a]
'b'     push             [a,b]
'b'     pop              [a]
'a'     pop              []
'c'     push             [c]
'a'     push             [c,a]

Then extracting:

stack: [c,a]
          ↑ top

pop a → ans = "a"
pop c → ans = "ac"

reverse("ac") → "ca"
Why this works conceptually

The really nice thing about the stack is that it automatically handles cascading removals.

Take:

"abbaca"

When bb disappears:

a b b a
  ↑ ↑
cancel

we get:

"aa"

and now those two as become adjacent and cancel too:

aa → ""

The stack naturally exposes the previous character after a pop.

That's why the pattern:

if (!st.empty() && c == st.top())
    st.pop();
else
    st.push(c);

is so powerful for adjacent duplicate removal.
