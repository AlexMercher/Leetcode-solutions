# Upcoming Question
Suppose there are lots of incoming s, say s1, s2, ..., sk where k >= 109, and you want to check one by one to see if t has its subsequence. In this scenario, how would you change your code?

Now the problem changes.

t is fixed, but you may receive billions of different s strings.

Doing:

scan t for every s

is wasteful.

The important observation is:

Preprocess t once so that we can quickly find the next occurrence of any character.

Since characters are lowercase English letters, build:

vector<int> pos[26];

where:

pos[0] = positions of 'a' in t
pos[1] = positions of 'b'
...

For:

t = "ahbgdc"

we get roughly:

a → [0]
b → [2]
c → [5]
d → [4]
g → [3]
h → [1]

Then for each character of s, find the first occurrence after the current position using upper_bound().

Code
class Solution {
public:
    vector<int> pos[26];


    void preprocess(string t) {
        for(int i = 0; i < t.size(); i++) {
            pos[t[i] - 'a'].push_back(i);
        }
    }


    bool isSubsequence(string s, string t) {
        // Preprocess only once in real usage.
        preprocess(t);


        int prev = -1;


        for(char c : s) {
            auto &v = pos[c - 'a'];


            auto it = upper_bound(v.begin(), v.end(), prev);


            if(it == v.end())
                return false;


            prev = *it;
        }


        return true;
    }
};

For many queries, you'd call preprocess(t) once, not every time.

Then each query costs roughly:

O(|s| log |t|)

instead of:

O(|t|)

per query.

Even better for this exact problem

Because the alphabet has only 26 characters, you can precompute a next[position][character] table.

Then each character lookup is O(1):

next[i][c] = next position >= i containing character c

That gives:

Preprocessing: O(26 * |t|)
Each query:     O(|s|)

For the stated follow-up with an enormous number of queries, this is the ideal approach.

So the progression to remember is:

One query:
    two pointers → O(|t|)


Many queries, t fixed:
    preprocess t
        ↓
    fast next-occurrence lookup
        ↓
    each s processed in O(|s|)

That is the classic preprocessing for repeated subsequence queries pattern.
