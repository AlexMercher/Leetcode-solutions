## Explanation

# Sum Game — Explanation

Split `num` into two halves and calculate:

- `leftSum` = fixed-digit sum on the left
- `rightSum` = fixed-digit sum on the right
- `leftQ` = number of `?` on the left
- `rightQ` = number of `?` on the right

If the total number of `?` is odd, Alice makes the final move, so she can force the two sums to be unequal.

When the total number of `?` is even, Bob makes the final move. The fixed digits create an imbalance:

leftSum - rightSum
The unequal number of ? positions creates a possible correction. Each unmatched pair of ? can change the difference by at most 9.

The required correction is:

9 * (rightQ - leftQ) / 2

The direction matters, so do not use abs().

Bob can force equality only when:

2 * (leftSum - rightSum) == 9 * (rightQ - leftQ)

Therefore Alice wins when they are not equal.

Time: O(n)
Space: O(1)

# Mistakes

1. Checking only the final total sum is insufficient because `?` positions are controlled by players.
2. The odd/even `?` case was initially reversed: odd → Alice wins immediately.
3. Do NOT use `abs()` for the final comparison; the direction of the imbalance matters.
4. `leftSum - rightSum` must be compared against the signed correction from `rightQ - leftQ`.
5. Use `2 * diff == 9 * qdiff` to avoid integer-division ambiguity.
