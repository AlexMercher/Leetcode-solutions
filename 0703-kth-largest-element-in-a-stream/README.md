## Explanation

Why min-heap?

Take:

k = 3
nums = [4,5,8,2]

We only want the 3 largest:

4, 5, 8

A min-heap stores them like:

        4  ← top (smallest)
       / \
      8   5

The smallest among these 3 is 4.

And that's exactly the 3rd largest.

Now add(3):

4,5,8 + 3

Heap temporarily contains:

3,4,8,5

Size became 4, so remove the smallest:

remove 3

Now:

4,5,8

pq.top() is:

4

So the 3rd largest is 4.

Why do we remove when size > k?

Suppose:

k = 3

and we have:

[10, 8, 7, 4, 2]

We only care about:

10, 8, 7

because everything smaller can never become the 3rd largest while these three are present.

So maintain:

heap size <= k

After every insertion:

pq.push(val);

if (pq.size() > K)
    pq.pop();

The smallest of the surviving k elements is always the kth largest.

Complexity

Each insertion:

$$ O(\log k) $$

Initialization:

$$ O(n\log k) $$

Space:

$$ O(k) $$
Pattern to remember

Whenever the question asks:

"Maintain the kth largest element in a stream."

Think:

k largest elements
        ↓
min-heap of size k
        ↓
heap.top() = kth largest

And the opposite problem, kth smallest, uses a max-heap of size k.
