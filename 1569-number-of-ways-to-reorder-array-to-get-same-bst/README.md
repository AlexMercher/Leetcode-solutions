## Explanation

Both [2,1,3] and [2,3,1] create this exact BST.
Why? The root 2 must be inserted first. Values smaller than 2 go into the left subtree, while values larger than 2 go into the right subtree. The order in which we interleave those left-side and right-side values can vary without changing the final tree.
But [3,2,1] starts with 3, so it creates a different root and thus a different BST.
2. The key observation: count interleavings
Suppose the input is:
nums = [3, 4, 5, 1, 2]


The root is 3, so partition the remaining elements:
Left subtree:  [1, 2]    size = 2
Right subtree: [4, 5]    size = 2


The left elements must retain an ordering that produces the same left subtree, and the right elements must retain an ordering that produces the same right subtree.
But we can interleave the two groups in multiple ways:
[1, 2, 4, 5]
[1, 4, 2, 5]
[1, 4, 5, 2]
[4, 1, 2, 5]
[4, 1, 5, 2]
[4, 5, 1, 2]


All six preserve the relative order within each group.

Let:
- (n) = number of nodes in the current subtree.
- (L) = number of nodes in its left subtree.
- (R) = number of nodes in its right subtree.
The root occupies the first position, leaving (n-1) elements.
We choose which (L) of those positions are occupied by elements from the left subtree. The remaining positions belong to the right subtree.

Base case: An empty tree or a tree with one or two nodes has exactly one ordering that produces the same BST. For two nodes, the root is fixed and the other node has only one possible position.
Finally, subtract one to exclude the original nums ordering.

### Complexity:
TC: O(n^2)
SC: O(n^2)
