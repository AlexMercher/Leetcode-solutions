## Explanation

visited prevents using the same cell twice in one path. dfs(row,col,index) means: we have successfully matched word[0..index] and are currently at (row,col).
For every neighbor:
if(out of bounds) continue;
if(visited[nr][nc]) continue;
if(board[nr][nc] != word[index+1]) continue;

These are branch-pruning checks. If a neighbor cannot possibly continue the word, we don't recurse into it.
Before DFS, we compare character frequencies in the board and word. If the board doesn't contain enough of any required character, the answer is immediately false.
Then, if the last character of the word is rarer than the first, we reverse the word. A valid path can simply be traversed backwards, so the answer doesn't change, but we may reduce the number of starting cells significantly.
Backtracking:
visited[nr][nc] = 1;
if(dfs(...)) return true;
visited[nr][nc] = 0;

The unmarking allows other paths to reuse that cell in different branches.

## My Notes

## Intution and Approach

Treat the problem as backtracking on the grid. Start only from cells matching word[0]. At each step, try the 4 neighboring cells. A move is valid only if it is inside the board, unused, and matches the next character. Mark the cell before recursion and unmark it after the branch fails.
Before DFS, prune impossible cases using character frequencies. Also reverse the word when its last character is rarer, reducing the number of starting positions and therefore the search tree.
