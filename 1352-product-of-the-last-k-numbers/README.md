## Explanation

Suppose:

add(3)
add(2)
add(0)
add(5)

After 0, we reset:

prefix = [1]

Then 5:

prefix = [1, 5]

Now:

getProduct(1)

works:

5 / 1 = 5

But:

getProduct(2)

asks for:

0 * 5

which must be 0.

Our current prefix contains only the numbers after the last zero:

prefix.size() = 2
k = 2

Since:

k >= prefix.size()

we return 0.

Visualize the indexing

Suppose:

add(3)
add(2)
add(5)

We have:

index:   0   1   2   3
prefix:  1   3   6  30

For:

getProduct(2)

we want:

2 * 5 = 10

Formula:

prefix.back() / prefix[prefix.size() - k - 1]

becomes:

30 / prefix[3 - 2 - 1]
30 / prefix[0]
30 / 1

Wait — this indexing is wrong for this representation. Since prefix has one extra initial 1, for last k elements we need:

prefix.back() / prefix[prefix.size() - 1 - k]

For k=2:

30 / prefix[0] = 30

Still wrong because prefix is [1,3,6,30]; the product before the last 2 numbers is 3, which is at index 1.

So the correct formula is:

prefix.back() / prefix[prefix.size() - 1 - k]

Let's calculate carefully:

prefix.size() = 4
k = 2

index = 4 - 1 - 2 = 1

30 / prefix[1]
30 / 3
= 10
