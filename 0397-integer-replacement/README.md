## Explanation

Why the condition works

For an odd number, the last bit is always 1.

So we look at the second bit from the right:

x & 2

because:

2 = 00010

Therefore:

x & 2 == 0

means the number ends in:

...01

For example:

5 = 101
      ↑ second-last bit = 0

So decrement:

5 → 4 → 2 → 1

But:

7 = 111
      ↑ second-last bit = 1

so increment:

7 → 8 → 4 → 2 → 1

The special case:

x == 3

must decrement:

3 → 2 → 1

rather than increment:

3 → 4 → 2 → 1

Both eventually reach 1, but decrementing takes fewer operations.

Why long long x = n?

This protects the x++ operation when:

n = INT_MAX

because:

INT_MAX + 1

cannot fit in a 32-bit int.

So your final implementation has both important pieces right:

odd number
    ↓
x == 3              → x--
otherwise x & 2 == 0 → x--
otherwise            → x++

This is the standard greedy solution and runs in O(log n) time with O(1) extra space.
