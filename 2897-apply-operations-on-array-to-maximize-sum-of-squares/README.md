## Explanation

You choose two numbers, x and y, and replace them with:
x = x & y;
y = x | y;  // Conceptually, this uses the ORIGINAL x and y.


The important word in the problem is simultaneously: both new values are calculated from the original values.
Consider this example:
x =  6 = 0110
y =  9 = 1001


Applying AND and OR gives:
AND = 0000 = 0
 OR = 1111 = 15


So the two numbers become 0 and 15.
Notice what happened: the set bits from both numbers have been collected into one number.

The number of occurrences of each bit never changes. A bit can move from one number to another, and we can combine bits from different numbers, but we cannot create or destroy a set bit.
That gives us our first important observation:
Count how many numbers contain each bit. Those counts tell us exactly how many copies of each bit are available to distribute.

2. Why does the problem ask for squares?
Because putting bits together makes the sum of squares larger.

Concentrate as many available bits as possible into the same selected numbers. We need to build k numbers whose sum of squares is maximum.

Suppose one bit occurs twice and another bit occurs once. We should put the single occurrence into the first number, rather than the second, so it combines with one of the occurrences of the other bit.
More generally, assigning every bit to the first available numbers makes as many bits as possible overlap in the same numbers. Because squares reward combining values, this maximizes the sum.
If a bit occurs more than k times, we put it into all k numbers. Any extra copies can remain in the other array elements because we only choose k elements for our sum.

Let (n) be the length of nums. Since the number of bit positions is fixed at 31:
- Time: (O(31n+31k)=O(n+k)).
- Extra space: (O(1)), because bitCount always has 31 entries.
