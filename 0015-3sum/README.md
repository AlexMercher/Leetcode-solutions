The important mental model of your code

For every fixed i:

nums[i] + nums[j] + need = 0

so:

need = -nums[i] - nums[j]

seen contains the values that appeared before the current j.

So when you find:

seen.find(need)

you're effectively asking:

"Have I already seen the third number needed to complete this triplet?"

For example:

i = -1
j = 1

need = 0

seen = {-1, 0}
              ↑
          found!

-1 + 0 + 1 = 0

And your set has one job:

Even if the same triplet gets discovered multiple times, keep only one copy.

That's why your approach handles cases like:

[0,0,0,0,0,0,...]

correctly, especially with:

if(i > 0 && nums[i] == nums[i-1])
    continue;

because all those 0s only need to be processed once.
