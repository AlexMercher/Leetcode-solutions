## Explanation

Why only start when x - 1 doesn't exist?

Take:

nums = [100,4,200,1,3,2]

Set:

{1,2,3,4,100,200}

Consider 1:

0 doesn't exist

So 1 is the start of a sequence.

Count:

1 → 2 → 3 → 4

Length = 4.

Now consider 2:

1 exists

So don't start another sequence from 2.

Likewise:

3 → 2 exists
4 → 3 exists

So we don't repeatedly scan:

1,2,3,4
2,3,4
3,4
4

We only scan it once.

Dry run
nums = [100,4,200,1,3,2]

Set:

{1,2,3,4,100,200}

Start:

ans = 0
x = 100

Check:

st.find(99)

not found → start sequence.

100 → 101

101 doesn't exist.

len = 1
ans = 1
x = 4

Check 3.

It exists, so:

skip
x = 200

Check 199.

Not found.

200 → 201

201 doesn't exist.

len = 1
ans = 1
x = 1

Check 0.

Not found → start.

1 → 2 → 3 → 4

Length:

4

So:

ans = 4
x = 2

Check 1.

Exists → skip.

x = 3

Check 2.

Exists → skip.

Final:

4
Why is it actually O(n)?

At first the nested while looks like O(n²), but it isn't.

Every sequence is scanned only from its beginning.

For:

1,2,3,4

we scan:

1 → 2 → 3 → 4

once.

When we later see 2, 3, or 4, we don't enter the while.

So across the entire algorithm, each number participates in the forward scan at most once.
