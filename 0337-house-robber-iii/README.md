## Explanation

for each node, we calculate both possibilities simultaneously:

What is the maximum money from this subtree if I rob this node?
What is the maximum money from this subtree if I do not rob this node?

That is the cleanest state definition.

The two states

For every node, maintain:

rob  = maximum money if we rob this node
skip = maximum money if we do not rob this node
If we rob the current node

We cannot rob its direct children.

So:

rob = node->val
      + left.skip
      + right.skip
If we skip the current node

Then we are free to either rob or skip each child:

skip = max(left.rob, left.skip)
     + max(right.rob, right.skip)

So every node returns:

{rob, skip}

Why this is DP

This is Tree DP.

The important difference from your earlier House Robber I is that the state is attached to a tree node, not an array index.

The generic pattern is:

For every node:
    solve left subtree
    solve right subtree
    combine their states

And here the state is:

dp[node][2]

state 0 → don't rob node
state 1 → rob node

So your intuition that “we need two DP values” is exactly right.

The more precise mental model is:

          node
       /       \
     child     child
       ↓         ↓
   {rob,skip} {rob,skip}
       ↓         ↓
        combine
           ↓
      {rob, skip}

This is a very important Tree DP pattern: take / skip state.

Whenever you see:

Select nodes from a tree, but selecting a node prevents selecting its directly connected neighbors

immediately think:

rob this node
vs
don't rob this node

and compute those two values for every subtree.

## My Notes

### Mistakes
I was forcing the robbing of the child if the parent did not get robbed and thus was losing the optimal answer.

This is the important distinction:

skip means we skip robbing the CURRENT node. It does NOT mean we skip its children.

So if we do:

int skip = max(left.first, left.second)
         + max(right.first, right.second);

we are saying:

Since I am not robbing this node, I am now free to choose the better option for each child independently.

Why not left.first + right.first?

Because left.first means:

We are definitely robbing the left child.

But skipping the current node does not force us to rob the child.

For example:

      10
      /
     5
    /
   20

If we skip 10, the best choice for the left subtree might actually be to skip 5 and rob 20.

So:

skip 10
    ↓
don't rob 10
    ↓
left subtree is completely free
    ↓
choose best of:
    rob 5
    skip 5

That's exactly what the max() represents.

Think of the two states like this

For every node:

rob[node]
    → I HAVE ROBBED this node
    → therefore children MUST be skipped

skip[node]
    → I DID NOT ROB this node
    → therefore children can be either robbed OR skipped

So:

rob = root->val
    + left.second
    + right.second;

because children must be skipped.

But:

skip = max(left.first, left.second)
     + max(right.first, right.second);

because children are now free to choose their better state.

The key rule to memorize
Current node ROBBED
        ↓
children MUST SKIP

Current node SKIPPED
        ↓
children can ROB or SKIP
        ↓
take MAX of both

This is the standard take/skip Tree DP pattern.

Your original thought of:

left.first + right.first

would actually mean:

"I skipped the current node, but I am forcing both children to be robbed."

That's unnecessarily restrictive, so you'd potentially lose the optimal answer.
