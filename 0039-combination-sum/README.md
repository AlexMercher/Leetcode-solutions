## Explanation

For normal combination problems where an element can be used only once:

backtrack(..., i + 1, ...);

Here, an element can be used unlimited times:

backtrack(..., i, ...);

That one line is extremely important.

Example
candidates = [2,3,6,7]
target = 7

Start:

[]

Choose 2:

[2]

Since 2 can be reused:

[2,2]

Again:

[2,2,2]

Target is now 1, so 2 can't be chosen.

Backtrack:

[2,2]

Try 3:

[2,2,3]

Target becomes 0 → store it.

Then eventually:

[7]

Final:

[
    [2,2,3],
    [7]
]
Why don't we get [3,2,2] too?

Because we only allow the recursion to choose candidates from index onward.

Once we've chosen:

2

we can choose:

2, 3, 6, 7

but after choosing 3, we never go backward and choose 2.

So we generate:

[2,2,3]

but not:

[2,3,2]
[3,2,2]

This is exactly how we avoid duplicate combinations.

Mental model

Think of index as:

"I am allowed to use candidates from here onward."

For:

[2,3,6,7]

choosing 2 means:

index = 0

and because reuse is allowed:

[2]
   ↓
backtrack(..., 0)

Choosing 3 then means:

[2,3]
     ↓
backtrack(..., 1)

So the tree only moves forward, but can stay at the same candidate.

That gives the two rules:

Reuse allowed      → recurse with i
Reuse not allowed  → recurse with i + 1

Combinations       → don't go backwards
Permutations       → can go backwards
