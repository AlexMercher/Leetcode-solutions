## Explanation

For:

1 → 2 → 3 → 3 → 4 → 4 → 5

Start:

prev
 ↓
dummy → 1 → 2 → 3 → 3 → 4 → 4 → 5
             ↑
            curr

3 is duplicated because:

curr->val == curr->next->val

So we skip all 3s:

curr → 4

and do:

prev->next = curr;

giving:

dummy → 1 → 2 → 4 → 4 → 5

Then we find the duplicate 4, skip both:

dummy → 1 → 2 → 5
Why prev does NOT move when we find a duplicate

This is the important part.

Suppose:

1 → 3 → 3 → 4

When we detect the duplicate 3, prev is still at 1.

After skipping both 3s:

1 → 4

So:

prev->next = curr;

can connect 1 directly to 4.

If you moved prev onto a duplicated node, you'd accidentally keep it.
