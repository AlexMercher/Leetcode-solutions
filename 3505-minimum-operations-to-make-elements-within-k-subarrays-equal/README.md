## Explanation

# Minimum Operations to Make K Non-Overlapping Subarrays Equal

## 1. Problem Understanding

We are given an array `nums`, window size `x`, and number of windows `k`.

We need to select at least `k` non-overlapping subarrays of length exactly `x`, such that all elements within each selected subarray become equal.

Each increment or decrement of an element costs one operation.

Our goal is to minimize the total operations.

We solve this using two techniques:

1. Sliding Window Median
2. Dynamic Programming

## 2. Sliding Window Median

To make all elements of a subarray equal with minimum operations, we must make every element equal to the median.

The minimum cost is:

`cost = sum of absolute differences from the median`

Instead of sorting every window independently, we maintain two multisets:

- `left`: Stores the smaller half of the current window, including the median.
- `right`: Stores the larger half of the current window.

We also maintain their sums:

- `sumLeft`
- `sumRight`

The median is:

`median = *left.rbegin()`

We maintain these properties:

1. `left` contains `(window size + 1) / 2` elements.
2. Every element in `left` is less than or equal to every element in `right`.

### Calculate the window cost

Since every element in `left` is less than or equal to the median:

`leftCost = median * left.size() - sumLeft`

Similarly:

`rightCost = sumRight - median * right.size()`

Therefore:

`cost = leftCost + rightCost`

We can calculate the cost in O(1) once the two multisets are maintained.

### Sliding the window

Whenever the window moves:

1. Insert the incoming element.
2. Remove the outgoing element.
3. Rebalance the two multisets.
4. Calculate the new window cost.

We store the cost of every possible window in:

`vector<long long> cost(n - x + 1);`

Each insertion and removal takes O(log x), so calculating all window costs takes O(n log x).

## 3. Dynamic Programming

After calculating all window costs, we no longer need the original array for the DP stage.

Define:

`dp[i][j]`

Meaning: Minimum cost of selecting exactly `j` non-overlapping windows from the first `i` elements.

We have two choices:

### Choice 1: Skip the current position

We do not select a window ending at the current position.

`dp[i][j] = dp[i - 1][j]`

### Choice 2: Select the last x elements

The selected window starts at index `i - x`.

Its cost is:

`cost[i - x]`

Since windows cannot overlap, previously selected windows must fit within the first `i - x` elements.

Therefore:

`dp[i][j] = dp[i - x][j - 1] + cost[i - x]`

### Final recurrence

`dp[i][j] = min(dp[i - 1][j], dp[i - x][j - 1] + cost[i - x])`

We initialize:

- `dp[i][0] = 0`, because selecting zero windows costs nothing.
- All other states are initially infinity.

The final answer is:

`dp[n][k]`

## 4. Space Optimization

We do not need the complete two-dimensional DP table.

For calculating the current number of windows `j`, we only need:

- The previous DP layer (`j - 1`).
- The current DP layer (`j`).

Therefore, we maintain two arrays:

`previous` and `current`.

After completing each DP layer, we swap them.

This reduces DP space from O(nk) to O(n).

## 5. Why Exactly K Windows Is Sufficient

The problem asks for at least `k` windows.

However, every window has a non-negative cost.

If we select more than `k` windows, we can simply discard some of them until exactly `k` remain.

The remaining windows are still non-overlapping, and the total cost cannot increase.

Therefore, finding exactly `k` windows is sufficient.

## 6. Complexity Analysis

| Component | Time Complexity | Space Complexity |
|---|---|---|
| Sliding Window Median | O(n log x) | O(x) |
| Window Cost Array | O(n) | O(n) |
| Dynamic Programming | O(nk) | O(n) |

**Overall Time Complexity:**

`O(n log x + nk)`

**Overall Auxiliary Space Complexity:**

`O(n + x)`

## 7. Important Takeaways

1. The median minimizes the sum of absolute differences.
2. Two multisets can efficiently maintain the median of a sliding window.
3. Maintaining the sums of both halves allows us to calculate the window cost in constant time.
4. DP helps us select non-overlapping windows optimally.
5. DP can be space-optimized when the current layer depends only on the previous layer.

**Overall approach:**

Original Array → Sliding Window Median → Precomputed Window Costs → Dynamic Programming → Minimum Operations.
