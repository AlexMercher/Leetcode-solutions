## Explanation

Classic backtracking here choose explore and delete

The core idea is:

At every index, choose every possible substring starting there. If that substring is a palindrome, add it to the current partition and recursively solve the remaining suffix.

For:

s = "aab"

Start at index 0:

"a"  → palindrome ✓
"aa" → palindrome ✓
"aab" → not palindrome

So we branch:

"a"
 ↓
remaining "ab"

"aa"
 ↓
remaining "b"

Then continue recursively.

Generic state
start

means:

We still need to partition s[start ... n-1].

Maintain:

vector<string> current;

which contains the palindrome pieces chosen so far.

Base case

When:

start == n

we have consumed the entire string, so current is one complete answer:

ans.push_back(current);

Dry run for "aab"

At start = 0:

"a"  ✓

Choose "a":

current = ["a"]

Now start = 1:

"a" ✓
"ab" ✗

Choose "a":

current = ["a","a"]

Now:

start = 2
"b" ✓

Choose "b":

current = ["a","a","b"]

start == n:

["a","a","b"]

Backtrack.

At start = 0, choose "aa":

current = ["aa"]

Then "b":

["aa","b"]

So we get:

[
    ["a","a","b"],
    ["aa","b"]
]
The generic pattern to remember

This is one of the most important "generate all valid partitions" patterns:

START at an index
      ↓
Try every possible end position
      ↓
Is s[start...end] valid?
      ↓ yes
Choose it
      ↓
Recurse from end + 1
      ↓
Undo the choice
      ↓
Try the next end

So don't think:

"I need to find all palindromes first."

Think:

"At each position, what are all possible next pieces I could choose?"
