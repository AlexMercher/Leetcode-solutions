## Explanation

The next pointers are initially NULL, but we build them as we traverse the tree. So when we write:

root->right->next = root->next->left;

we are assuming that root->next has already been populated.

The recursion/order makes that true.

Look at this tree
             1
          /     \
         2       3
       /  \     /  \
      4    5   6    7

Initially:

1.next = NULL
2.next = NULL
3.next = NULL
...

We start at 1.

For root 1:

root->left->next = root->right;

so:

2.next = 3

Now we recurse.

But here's the important part:

solve(root->left);
solve(root->right);

First we call:

solve(2)

At this moment, 2->next is already 3, because we just created that connection while processing 1.

So inside solve(2):

root = 2
root->next = 3

Therefore:

root->right->next = root->next->left;

becomes:

5->next = 3->left;

which is:

5.next = 6

So now:

4 → 5 → 6

Then we process 3 and create:

6 → 7
The dependency is
Parent level creates next pointers
            ↓
Child level uses those next pointers

Specifically:

1
↓
creates 2 → 3
↓
when processing 2:
use 2.next (= 3)
↓
create 5 → 6

So the recursion is effectively processing the tree level by level in terms of next-pointer availability, even though it's technically DFS recursion.
