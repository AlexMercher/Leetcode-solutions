## Explanation

Let mn be the smallest character and mx the largest character.
Case 1: Already sorted → 0 operations
If s is already in non-decreasing order, no operation is needed.

Example: "abc" → 0

Case 2: First character is minimum OR last is maximum → 1 operation
If s[0] == mn, sort the suffix s[1...n-1].

If s[n-1] == mx, sort the prefix s[0...n-2].

Example: "dog" → sort "og" to get "dgo".

The endpoint that is already correct stays untouched.

Case 3: Two operations are usually enough
If neither one-operation condition holds, we can generally sort the string in two operations.

Example: "card" → "acrd" → "acdr".

Case 4: Unique maximum first, unique minimum last → 3 operations
Example: "cba".

The maximum c is at the beginning, and the minimum a is at the end. Both occur only once.

Neither endpoint can be fixed in one operation because an operation cannot include the entire string. In this special case, we need three operations.


There is one more edge case: if n == 2 and the string is not sorted, the answer is -1. Every allowed substring has length one, so no operation can change the string.
2. Why do duplicates matter?
Consider "caa".

The first character is the maximum and the last character is the minimum, but the minimum a appears twice. Therefore, we can sort in two operations:
caa → aca → aac


Compare that with "cba":
cba → bca → bac → abc


Here, both the maximum and minimum are unique, so three operations are necessary.

This is why we must check the frequencies of the minimum and maximum, not just their positions.
