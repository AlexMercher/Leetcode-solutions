## Explanation

Suppose:
user 1 follows user 2

Tweets:
user 1:
(1,5)

user 2:
(2,6)

getNewsFeed(1):
Initial heap:
(1, user1, index0)
(2, user2, index0)

Top:
(2, user2)

So:
ans = [6]

User 2 has no older tweets.
Next heap:
(1, user1)

So:
ans = [6,5]

Exactly what we want.
idx is simply the index of the tweet inside that user's tweet vector.
Remember:
vector<vector<pair<int,int>>> tweets;

and for a user:
tweets[userId]

might contain:
index:        0          1          2
             ↓          ↓          ↓
tweets[2] = [(1,50), (4,60), (8,70)]
             ↑time      ↑time      ↑time

Because tweets are added chronologically, the latest tweet is at the back.
So:
int idx = tweets[userId].size() - 1;

means:
Give me the index of this user's latest tweet.

For the example above:
size = 3
idx = 3 - 1 = 2

So:
tweets[userId][idx]

is:
(8,70)

where:
.first  = timestamp
.second = tweetId

That's why we put:
pq.push({
    tweets[userId][idx].first,
    userId,
    idx
});

into the heap:
(timestamp, which user, which tweet index)

Why do we need idx in the heap?
After we pop the latest tweet of that user, we need to know:
"What is that user's next older tweet?"

That's simply:
idx - 1

So if:
tweets[2] = [(1,50), (4,60), (8,70)]
                      ↑      ↑
                    idx=1  idx=2

we pop index 2 (70), then push index 1 (60).
So the mental model is:
idx tells us exactly where we currently are in that user's tweet history.

It's essentially a pointer into that user's sorted tweet list.
