## Explanation

# Lexicographically Smallest Palindromic Permutation — Approach

## 1. Check Whether a Palindrome Is Possible

Count the frequency of every character.

A palindrome is possible only when:

- `n` is even → exactly `0` odd-frequency characters.
- `n` is odd → at most `1` odd-frequency character.

Store the odd-frequency character as `middle`.

---

## 2. Build Only the Left Half

A palindrome is completely determined by its left half and, for odd length, its middle:

```text
PALINDROME = half + middle + reverse(half)

Construct half using freq[c] / 2 copies of every character.

3. Compare Against Target

Only the left half needs to be constructed first.

Try to make the left half equal to:

target[0 ... half.length()-1]

Maintain a frequency array cnt for the remaining characters.

If targetHalf[i] exists:

ansHalf.push_back(targetHalf[i]);
cnt[targetHalf[i] - 'a']--;

Continue.

4. If We Cannot Continue

At position i, try the smallest available character strictly greater than:

targetHalf[i]

Once such a character is found, the prefix is already as small as possible and the remaining characters should be placed in ascending order.

Then construct:

newHalf + middle + reverse(newHalf)

and return it.

5. If the Entire Half Matches

The exact half does not automatically mean the final palindrome is greater.

Construct the complete palindrome:

half + middle + reverse(half)

and compare it directly with target.

If it is greater, return it.

Otherwise, backtrack through the half from right to left and find the rightmost position that can be increased.

6. Backtracking

For each previous position:

Restore its character to cnt.
Try the smallest available character greater than the target character.
Fill the remaining half in ascending order.
Mirror the half.

If no position can be increased:

return "";
Core Pattern
frequency of s
      ↓
can a palindrome exist?
      ↓
build LEFT HALF
      ↓
match target half
      ↓
cannot continue?
      ↓
increase current/rightmost possible position
      ↓
fill remaining characters minimally
      ↓
mirror

The central idea is:

Because a palindrome is determined by its first half, perform the lexicographical construction on the half instead of the complete string.

## My Notes

# Mistakes

1. Counting even frequencies instead of odd frequencies caused zero-frequency characters to be counted incorrectly.

2. The middle character must be:
```cpp
middle = 'a' + i;
not a fixed character.

The palindrome condition is:
odd <= n % 2

not odd <= n / 2.

We must compare the complete palindrome with target when the entire half matches. Checking only the middle misses cases like:
abb → bab.
Backtracking loops must use:
for(int c = cur + 1; c < 26; c++)

not cur < 26.

When constructing the remaining part, characters must be placed in ascending order to keep the result lexicographically smallest.
return "" is only reached after no position can be increased and therefore no valid palindrome is strictly greater than target.
