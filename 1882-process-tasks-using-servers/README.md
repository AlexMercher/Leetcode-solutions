## Explanation

Maintain two priority queue one for the available servers and other for the busy servers once the servers get free push to the available one and if tasks are assigned then push them to the busy one this ensures that we can get the servers which are free and busy automatically using the data structure property of the priority queue. 

TC:O(nlogn+mlogn)
SC:O(n)

## My Notes

This problem teaches three useful concepts:

1. Multiple Priority Queues

Sometimes one priority queue is insufficient because we need to prioritize different things depending on the current state.

Here:
- Available servers are prioritized by weight and index.
- Busy servers are prioritized by finishing time.
2. Event Simulation

Instead of incrementing time second by second, we jump directly to the next important event.

For example, when all servers are busy, we jump directly to the earliest server completion time.

This is called Event-Driven Simulation.

3. Tie-breaking

Whenever a problem says:
- Smallest weight, then smallest index.
- Earliest time, then smallest priority.
- Highest score, then smallest identifier.
Think about storing multiple fields in a pair or tuple inside a priority queue.
