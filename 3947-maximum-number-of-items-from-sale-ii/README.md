## Explanation

iota() is an algorithm from the C++ Standard Library (<numeric>). It fills a range with consecutive values, starting from a number you provide.

For example:
vector<int> arr(5);

iota(arr.begin(), arr.end(), 0);


Result:
arr = {0, 1, 2, 3, 4};


Let's understand its arguments:
iota(start, end, initial_value);


- arr.begin() points to the first position.
- arr.end() points just beyond the last position.
- 0 is the initial value.
It fills each position and increments the value by one.

Another example:
vector<int> arr(5);

iota(arr.begin(), arr.end(), 10);


Result:
{10, 11, 12, 13, 14}


Why are we using it in this problem?
vector<int> order(n);
iota(order.begin(), order.end(), 0);


We want:
order = {0, 1, 2, 3, ..., n-1};


These are the indices of the original items array.

We sort the indices instead of sorting items itself because we want to preserve the original relationship between each item's factor, price, and bonus.

For example:
items = {
    {1, 6},
    {2, 4},
    {3, 5}
};


Initially:
order = {0, 1, 2};


After sorting by price:
order = {1, 2, 0};


We can now access items in increasing price order:
- items[1] costs 4.
- items[2] costs 5.
- items[0] costs 6.
The original items array remains unchanged.

2. What is ranges::sort()?
C++20 introduced ranges algorithms, including ranges::sort().

The traditional sorting function is:
sort(arr.begin(), arr.end());


The newer version is:
ranges::sort(arr);


Both sort the array in ascending order.

For example:
vector<int> arr = {5, 2, 8, 1, 3};

ranges::sort(arr);


Result:
{1, 2, 3, 5, 8}


What is the advantage?
One advantage is that ranges::sort() can accept the entire container directly. You don't need to specify begin() and end().

It also supports something called a projection.

A projection tells the sorting algorithm which property of an element it should use for sorting.

For example:
vector<vector<int>> items = {
    {1, 6},
    {2, 4},
    {3, 5}
};

ranges::sort(items, {}, [](const auto& item) {
    return item[1];
});


This sorts the items by their price (item[1]), without needing to write a custom comparator.

The three arguments are:
ranges::sort(container, comparator, projection);


- container: What to sort.
- comparator: How to compare two projected values. {} means use the default ascending comparison.
- projection: Which value to extract from each element.
You can also use a comparator just like traditional sort():
ranges::sort(order, [&](int a, int b) {
    return items[a][1] < items[b][1];
});


Important: ranges::sort() does not have better time complexity than traditional sort(). Both generally take \(O(n\log n)\). It is mainly a more expressive interface.

Use #include <algorithm> and compile with C++20 or later for ranges::sort().

The optimization: Calculate bonus once per factor
Remember that the bonus depends on the factor, not the item's price or its position.

If two items have the same factor, their bonus is identical.

So instead of calculating the bonus for every item, calculate it once for every possible factor.
vector<int> total(n + 1, 0);

for (int f = 1; f <= n; f++) {
    for (int j = f; j <= n; j += f) {
        total[f] += freq[j];
    }
}


Now:
bonus[i] = total[items[i][0]] - 1;


Why subtract 1?

Because total[f] includes the item itself. We must exclude it, but other items with the same factor must still count.

In conclusion:
First, we calculate the frequency of every factor. Using a multiples-based approach, we precompute total[f], the number of items whose factors are divisible by f. Subtracting 1 gives the free-copy bonus for each item, excluding itself.

Next, we find the cheapest item price and sort item indices by price using iota() and ranges::sort().

The greedy strategy is that buying a bonus-eligible copy costs price and gives 2 copies. Buying the cheapest item normally gives 1 copy for minPrice. Therefore, we prioritize bonus-eligible purchases costing less than 2 * minPrice, processing cheaper ones first.

For each eligible item, we buy as many copies as its bonus and remaining budget allow. Finally, we spend the remaining budget on the cheapest item.

The result is the maximum total number of copies.
