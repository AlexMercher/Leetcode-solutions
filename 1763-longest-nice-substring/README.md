## Explanation

The key observation is:

If a character appears in a substring in only one case, that character cannot belong to any nice substring containing it.

For example:

s = "YazaAay"

Suppose we look at:

"YazaAay"

Y appears, but y does not.

Therefore no nice substring can contain that Y.

So we can split around it:

"Y" | "azaAay"

and recursively search the pieces.

The idea

For a substring s[l...r]:

Find which lowercase/uppercase pairs are incomplete.
If every character has both cases → the whole substring is nice.
Otherwise find a character c that appears only in one case.
That character cannot be part of any nice substring.
Split around it and solve the left and right parts.
Example
"YazaAay"

Y has no y.

So:

Y | azaAay

Now inspect:

"azaAay"

All characters?

a/A → both
z/Z → z exists, Z does not

So z is also a separator:

a | z | aAay

Now:

"aAay"

contains:

a and A

so it's nice.

Thus:

"aAa"

is the best answer.

How to check whether a character is "bad"

Use a 26-bit mask.

For a substring, maintain:

lowercase mask
uppercase mask

For example:

lower |= 1 << (s[i] - 'a'); for lowercase and:

upper |= 1 << (s[i] - 'A'); for uppercase.

Then a character is nice only if both bits exist.

lower & upper

contains the characters that have both cases.

So:

lower ^ upper

contains characters for which exactly one case exists.

That is useful for identifying a separator.
