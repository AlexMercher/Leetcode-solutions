# Strong Password Checker — Explanation

The problem has 3 independent requirements:

1. Length must be between 6 and 20.
2. Password must contain at least one lowercase letter, one uppercase letter, and one digit.
3. No character can appear 3 or more times consecutively.

## 1. Count Missing Character Types

Check whether the password contains:

- lowercase
- uppercase
- digit

Then:

```cpp
int missing = !lower + !upper + !digit;

For example, if only lowercase exists:

missing = 2

because uppercase and digit are missing.

2. Count Replacements Required

Find every consecutive run of the same character.

For a run of length len >= 3, the number of replacements needed is:

replace += len / 3;

Examples:

aaa       -> 1 replacement
aaaa      -> 1 replacement
aaaaa     -> 1 replacement
aaaaaa    -> 2 replacements
aaaaaaa   -> 2 replacements

The run is found using:

int j = i;


while (j < n && password[j] == password[i])
    j++;


int len = j - i;

j is the first position outside the run, so the length is j - i.

Case 1: Password Too Short

If:

n < 6

we need:

6 - n

insertions.

An insertion can also fix a missing character type or break a repeating sequence.

Therefore:

answer = max(6 - n, missing);

Example:

password = "a"


length needed = 5
missing types = 2


answer = max(5, 2) = 5
Case 2: Password Length Is Valid

If:

6 <= n <= 20

we don't need insertions or deletions.

We only need to fix:

missing character types
repeating sequences

A replacement can potentially fix both at the same time.

Therefore:

answer = max(replace, missing);

We use max, not addition.

Case 3: Password Too Long

If:

n > 20

we must delete:

deletions = n - 20;

However, deletions should be used intelligently.

Deleting characters from a repeating run can reduce the number of replacements required.

For a repeating run of length len:

len % 3 == 0
    1 deletion saves 1 replacement


len % 3 == 1
    2 deletions save 1 replacement


len % 3 == 2
    3 deletions save 1 replacement

Therefore, deletions should be prioritized in this order:

1. Runs where len % 3 == 0
2. Runs where len % 3 == 1
3. Remaining runs

After using the available deletions optimally:

answer = deletions + max(missing, replace);

The deletions are unavoidable because the password must be reduced to at most 20 characters.

Why the Greedy Deletion Order Works

Suppose we have:

aaaaaaaaaa

A long repeating run requires replacements.

Instead of simply deleting arbitrary characters, we want every deletion to reduce the replacement count as quickly as possible.

For a run:

len = 6


6 / 3 = 2 replacements

One deletion gives:

len = 5


5 / 3 = 1 replacement

So one deletion saved one replacement.

This is why runs with:

len % 3 == 0

are handled first.

Then we handle:

len % 3 == 1

and finally:

len % 3 == 2
Overall Strategy

The complete thought process is:

Check character requirements
        ↓
Count missing character types
        ↓
Find repeating runs
        ↓
Calculate replacement requirement
        ↓
Check password length
        ↓
   ┌────┴────┐
   ↓         ↓
 n < 6     n > 20
   ↓         ↓
insert    delete intelligently
   ↓         ↓
   └────┬────┘
        ↓
  6 <= n <= 20
        ↓
Use replacements

The three final cases are:

if (n < 6)
    return max(6 - n, missing);


if (n <= 20)
    return max(replace, missing);


// n > 20
return deletions + max(missing, replace);
Complexity

The password length is at most 50.

We scan the password a constant number of times.

Time Complexity: O(n)

Space Complexity: O(1)
