## Explanation

Take:

a = 1
b = 2

Binary:

1 = 001
2 = 010
Step 1: XOR
  001
^ 010
-----
  011

011 = 3.

Notice that XOR gives the correct sum when there is no carry.

But consider:

1 + 1

Binary:

  01
+ 01
----
  10

XOR gives:

01 ^ 01 = 00

The missing information is the carry.

Finding the carry

Two 1s in the same bit position produce a carry.

That's exactly what:

a & b

finds.

For:

1 = 001
1 = 001

we get:

001
&
001
---
001

Then shift left:

001 << 1 = 010

So:

carry = 2
So every iteration does two things
a = a ^ b;

means:

Add the two numbers without carry.

And:

b = carry;

means:

Now add the carry on the next iteration.

So conceptually:

sum without carry
        +
carry
        ↓
repeat
Dry run: 1 + 2

Initially:

a = 001
b = 010
Iteration 1

Carry:

001
010
---
000

000 << 1 = 000

So:

carry = 0

XOR:

001
010
---
011

So:

a = 011 = 3
b = 0

Loop ends.

Return:

3
More interesting example: 5 + 3
5 = 101
3 = 011

XOR:

101
011
---
110

So:

a = 6

Carry:

101

001

So:

Now we're effectively doing:

6 + 2

So:

a = 0

Carry:

So:

a = 8
b = 0

Return:

8
The pattern to remember

For binary addition:

XOR → sum without carry
AND → where carry happens
<< 1 → move carry to next bit

So:

carry = (a & b) << 1;
a = a ^ b;
b = carry;

Repeat until:

b == 0

because that means there is no carry left to process.
