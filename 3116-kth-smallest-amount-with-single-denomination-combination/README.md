# Kth Smallest Amount — Solution Explanation

## Core Idea

We cannot generate the first `k` amounts because `k` can be as large as `2 * 10^9`.

Instead, binary search the answer.

For a number `m`, define:

```text
check(m) = number of valid amounts <= m

If check(m) >= k, then the kth amount is <= m.

Otherwise, it is larger than m.

Therefore check(m) is monotonic and can be binary searched.

Counting Valid Amounts

An amount is valid if it is divisible by at least one coin.

For one coin c:

m / c

numbers up to m are divisible by it.

With multiple coins, numbers divisible by multiple coins are counted more than once, so we use Inclusion-Exclusion.

For every non-empty subset of coins:

1 coin chosen  → add
2 coins        → subtract
3 coins        → add
4 coins        → subtract
...

For a subset, every number divisible by all its coins must be divisible by their:

LCM (Least Common Multiple)

Therefore its contribution is:

m / LCM(subset)

The sign is:

(-1) ** (subset_size + 1)
Why Enumerating Subsets Works

There are at most 15 coins.

So the number of non-empty subsets is:

2^15 - 1 = 32767

which is manageable.

Binary Search

The smallest coin can always generate multiples:

coin, 2*coin, 3*coin, ...

Therefore:

high = k * min(coins)

is a safe upper bound.

We binary search for the smallest m satisfying:

check(m) == True

The compact Python implementation uses:

bisect_left(..., key=check)

which finds the first value for which check becomes true.

There are 2^n subsets and O(log(k * min(coins))) binary-search checks.

Time:  O(2^n * n * log(k * min(coins)))
Space: O(n)

The important pattern is:

Huge k
  ↓
Cannot generate answers
  ↓
Can we count answers <= X?
  ↓
Yes → Inclusion-Exclusion
  ↓
Count is monotonic
  ↓
Binary Search on Answer
