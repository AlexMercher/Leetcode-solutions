## Explanation

Suppose:

intervals:
0 = [1,3,2]
1 = [4,5,2]
2 = [1,5,5]
3 = [6,9,3]

Consider interval 2:

[1,5,5]

The next interval must start strictly after 5.

So:

next.left > 5

and interval 3 starts at 6.

Therefore:

next[2] = 3

If we take interval 2, our candidate becomes:

5 + dp[3][3]
6. Why a[i][1] + 1 in lower_bound?

We need:

start > right

But lower_bound(x) finds:

first value >= x

So to get:

first start > right

we search for:

right + 1

Since all coordinates are integers:

start > right

is equivalent to:

start >= right + 1

Hence:

lower_bound(starts.begin(), starts.end(), a[i][1] + 1);
7. Why do we process i backwards?

Because:

dp[i][k]

depends on:

dp[i+1][k]

and:

dp[next[i]][k-1]

Both are to the right of i.

So:

n-1 → n-2 → ... → 0

guarantees those states are already calculated.

8. The tie-breaking is the important part

Suppose:

skip:
score = 15
ids   = [2,5]

take:
score = 15
ids   = [1,6]

Scores are equal.

Then:

take.ids < skip.ids

is:

[1,6] < [2,5]

so we choose:

[1,6]

Exactly what the problem asks.

Because there are only 4 selected indices, doing:

take.ids.insert(...)

and comparing vectors is effectively constant work.

9. Complexity

Sorting:

O(n log n)

Finding next for every interval:

O(n log n)

DP:

O(n × 4)

Since the chosen vector has at most 4 elements, copying/comparing it is constant-sized.

Overall:

Time  = O(n log n)
Space = O(n)

with n <= 5 * 10^4.

Recognition pattern

When you see:

intervals
+
weight
+
non-overlapping
+
maximize total weight

think:

Weighted Interval Scheduling

Then this problem adds:

at most 4 intervals

so:

Weighted Interval Scheduling
        +
small k constraint
        ↓
DP[i][k]

And because the problem has a tie-break:

maximum score
→ lexicographically smallest indices

our DP state stores both:

(score, chosen indices)

The central recurrence is:

dp[i][k] =
    better(
        skip current,
        take current + dp[next[i]][k-1]
    )

The strict right < next.left condition is the one boundary detail to be especially careful about.
