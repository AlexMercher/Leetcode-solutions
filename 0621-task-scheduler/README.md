## Explanation

Did we finish all tasks, or are there still tasks waiting?

Case 1: pq is empty
Suppose:
tasks = [A,B,C]
n = 2

We use:
A B C

The block has 3 slots (n+1 = 3), and we filled all 3.
After processing:
pq.empty() == true

There are no more tasks, so we do not need to wait.
Thus:
if(!pq.empty())
    time += slots;

does nothing.
Case 2: pq is NOT empty
Suppose:
tasks = [A,A,A,B,B,B]
n = 2

First block:
A B _

We had 3 slots:
slots = 3

We scheduled:
A → slots = 2
B → slots = 1

Now the heap still contains tasks:
A, B

So:
!pq.empty()

is true.
There is:
slots = 1

unused interval.
That interval must be idle, because the remaining A and B are still cooling down.
So:
time += slots;

adds that idle time.
Now:
time = 3

and we begin the next block.
Why don't we add slots unconditionally?
Imagine:
tasks = [A,B,C]
n = 2

We fill the block completely:
A B C

After that:
slots = 0

so adding it wouldn't matter anyway.
But the real reason for the if is the last block.
Suppose:
A B
n = 2

We execute:
A B

There are technically:
slots = 1

left in the n+1 block.
But there are no remaining tasks.
We should return:
2

not:
3

So:
if(!pq.empty())
    time += slots;

means:
Only count the unused slots as idle time when there are still tasks left to perform.

That's the entire logic.
