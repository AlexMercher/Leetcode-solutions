## Explanation

Think of the segment tree like this:

             ┌───────────┴───────────┐
             │                       │
         whole product          prefix counts
             │                       │
       product % K          cnt[0], cnt[1], ...
             │
             └──────────────┐

                            │
             ┌──────────────┴──────────────┐
             │                             │
      prefixes ending in A        A + prefixes of B
             │                             │
          A.cnt[r]              A.prod * B.cnt[r] % K

ANSWER

The code translated into plain English

Main function is basically:

K = k
build the tree

for every query:

    change nums[index] to value

    look at nums[start ... n-1]

    find how many prefixes of that range
    have product % K == x

    store that number

And the node/merge machinery exists solely to answer:

"For this range, how many prefixes have each possible product remainder?"

Because k <= 5, we only need at most:

cnt[0]
cnt[1]
cnt[2]
cnt[3]
cnt[4]

That tiny state is what makes the segment tree practical.

Each segment-tree node summarizes a segment by its total product remainder and the remainder-count of every prefix; merging works because every prefix of A+B is either a prefix of A or A + a prefix of B.
