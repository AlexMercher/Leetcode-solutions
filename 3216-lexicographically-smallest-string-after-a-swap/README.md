## Explanation

Your condition:

((a & 1) == (b & 1)) && a > b

means:

a and b have the same parity (both odd or both even).
a > b, so swapping them puts the smaller digit first.

That is exactly when the swap is allowed and useful.

Why only adjacent digits?

The operation lets us swap adjacent digits only, and we only need to make the string smaller. So we scan from left to right and find the first place where a valid improving swap exists.

Because earlier digits have greater place value, fixing the earliest possible position gives the smallest number.

Dry run

Take:

s = "45320"

Indices:

4 5 3 2 0

Check 4,5:

4 even
5 odd

Different parity → cannot swap.

Check 5,3:

5 odd
3 odd
5 > 3

Same parity + decreasing → swap:

45320
  ↓
43520

Now stop because only one swap is allowed.

Result:

"43520"
Another example
s = "13542"

Check:

1,3 → both odd, but 1 > 3 ❌
3,5 → both odd, but 3 > 5 ❌
5,4 → different parity ❌
4,2 → both even and 4 > 2 ✅

Swap:

13542 → 13524
Why a > b?

Suppose:

... a b ...

If a < b, swapping gives:

... b a ...

which makes the number larger, so we don't want that.

If:

a > b

then:

... a b ...
↓
... b a ...

makes it smaller.

So the complete rule is:

same parity
+
left digit > right digit
        ↓
swap
