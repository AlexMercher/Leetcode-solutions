## Explanation

Consider:
nums = [3, 1, 2]


The sorted array is:
sorted = [1, 2, 3]


Because n = 3, the only possible values of k are 1 and 3.
- k = 1: Each block contains one element. No element can change its position, so the array cannot become sorted.
- k = 3: The whole array is one block. Rotating [3,1,2] produces [1,2,3], so k = 3 is valid.
Answer: 3.
The important observation
For a candidate k, divide both arrays into blocks of length k.

Each original block must be a cyclic rotation of the corresponding block in the sorted array.

For example:
Original: [2, 1 | 3, 4]
Sorted:   [1, 2 | 3, 4]


For k = 2, both blocks can be rotated independently into their respective sorted blocks. Therefore, k = 2 is valid.

We do not need to simulate the rotations. We only need to check whether each block is a cyclic rotation of its target block.
2. How do we check a cyclic rotation efficiently?
The target block is sorted. A sequence that is a rotation of a sorted sequence has at most one strict decrease when we compare its elements circularly, including the last element with the first.

For example:
Block: [3, 1, 2]

Circular comparisons:
3 > 1   decrease
1 < 2   no decrease
2 < 3   no decrease (wrap-around)


There is one decrease, so start immediately after it. The rotated sequence becomes [1,2,3].

But one decrease alone is not enough. We must also compare the rotated block element by element with its corresponding sorted block. This verifies that the values match exactly.

When operations rearrange elements only within fixed-size blocks, compare each block with the corresponding slice of the globally sorted array. Then determine whether the allowed operation can transform each block into that target.

Time Complexity: O(nlogn + nR(n)); R(n)=> finding the time for the divisors and then checking the valid K for them.

Space Complexity: O(n) For the sorted copy of the nums Array.
